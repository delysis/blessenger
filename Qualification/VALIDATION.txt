Continuation: cancellation callback lifetime correction
-----------------------------------------------------
The driver now retains callback storage through session and engine destruction.
Unlike the Session destructor's bounded wait, engine destruction joins the
execution/callback pools. Callback accessor/start failures terminate the isolated
qualification process instead of reporting a fictitious final callback or
unwinding storage that the runtime might still borrow.

After this driver-only correction, both actual C++ translation units compiled
again against the same real headers with the flags above, and the analyzer
self-tests passed. Actual command, exit status 0:

bash CallGemma/Qualification/build.sh \
  --headers /workspace/scratch/09e99beaae67/LiteRT-LM \
  --out /tmp/callgemma-callback-handoff-review

The earlier Validation/ source digest files identify the original portable run;
they are not a claim that native cancellation was tested after this correction.
Native cancellation, worker joins and all native gates remain NOT RUN.
